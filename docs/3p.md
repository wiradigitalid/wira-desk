### 2026-08-26 — DEC-006 applied: arrangement never targets a Wira Desk window

One decision written and, after the owner ratified it in session, applied the same day — plus `OQ-18`,
`OQ-19`, and a memlog (`.control/memlog/arrangement-self-targeting-2026-08-26.md`). Six documents
changed: `LBR-WM-6` and `LBR-ST-13` added, one SRS constraint, one `UC-2` alternate flow, and a note
each in `LC-arrangement-engine` and `LC-settings-shell`.

The decision was drafted first and held at `draft` with `touches: []` until then, because carrying a
draft into the documents it governs forges the evidence `applied` exists to record. The reserved-edits
table in the memlog is what made the apply mechanical — and it named documents rather than rule
numbers, which is why it survived `DEC-003`–`DEC-005` consuming `LBR-ST-10` through `12` in between.

`DEC-006` has two halves. Arrangement resolves no target when the foreground window belongs to Wira
Desk, gated in `resolve_context_for` and identified by executable basename; and the Settings window's
painted size is its Win32 size, clamped in `WM_WINDOWPOSCHANGING`.

What was not obvious, and is why this is a decision rather than a patch:

- **The proposed guard is already installed and already failing.** The consultation asked for a
  `WM_GETMINMAXINFO` clamp via `ptMaxTrackSize`. Slint sets the window non-resizable, winit writes
  `ptMaxTrackSize` from that, and the ghost frame appears anyway — those fields govern user
  drag-resize tracking and maximize, not an arbitrary `SetWindowPos`. Clamping there would have
  shipped as a guard that stops nothing. winit's `WM_WINDOWPOSCHANGING` handler, the one message that
  could refuse the resize, only tracks the monitor of a fullscreen window and never reads `cx`/`cy`.
- **The exclusion looks like the VM/RDP bypass and carries the opposite disposition.** That bypass
  passes the chord through, because it belongs to the guest. Passing `Ctrl+Win+Left` through here
  fires Windows' previous-virtual-desktop action — `reservation()` deliberately does not reserve
  `Ctrl+Win+Arrow` — so the gate has to swallow, which the hook already does for free before the
  Worker resolves a target. Same conclusion, different seam, and the Worker seam costs nothing on a
  callback budgeted under 10 ms.
- **Two halves, not one, because the exclusion fixes exactly one caller.** The same ghost frame is
  reachable by any third-party tiler or script with none of Wira Desk's code involved. The clamp is
  what makes the invariant true; the exclusion is what makes the product's own behaviour sensible.
- **The window class is not a usable discriminator.** The toolkit registers a generic one; the
  existing single-instance check reaches for the window *title*, which is worse. Executable basename
  extends the spine's existing executable-name identity rule, already ratified for cycling.

Drift found and deliberately left for `wdi-reconcile`: the spine's Settings-binary entry and
`LC-settings-shell` still describe an egui/eframe presentation layer, while `crates/settings` is
Slint 1.17 with the Skia renderer.

### 2026-08-26 — DEC-003 and DEC-004 drafted: Windows-reserved hotkey policy and the recorder lease

Two decisions written as `status: draft`, plus `OQ-16` and a memlog
(`.control/memlog/reserved-hotkey-policy-2026-08-26.md`):

- **`DEC-003`** — a chord the Windows shell owns is refused and explained, never overridden. The
  load-bearing reason is not muscle memory but daemon liveness: an override makes one chord do two
  different things depending on whether the tray process is alive, and the user can see neither state
  at the moment they press it. Two kinds of entry, because `Ctrl+Alt+Del` and `Win+L` cannot be taken
  at all, so offering an alternative for them would be a promise nothing can keep.
- **`DEC-004`** — while a field is listening, the hook swallows the chord and posts the virtual-key
  code back to Settings. Not optional: without it the refusal `DEC-003` requires can never reach the
  screen, because Explorer acts, Settings loses focus, and the toolkit never sees the key event.

What was not obvious, and is why these are decisions rather than a patch:

- The existing capture lease is checked **after** the `match_shortcut` early return, so it engages
  only for an already-configured chord. It was proposed as the place this feature goes; it is the
  thing that has to be inverted for the feature to exist.
- The lease returns passthrough **by design**, so the toolkit can see the chord — and passthrough is
  exactly what lets Explorer steal focus. The two requirements are mutually exclusive.
- `Alt+Backtick` is not reserved by Windows at all. It is this product's own
  `switcher.fallback_shortcut` default, and denylisting it would make the shipped default fail its
  own validation. Only the recorder's text-derived key name fails on it.
- The denylist lives in `settings`, so the daemon never consults it, and the daemon has **two**
  config paths with deliberately different semantics (`config.rs::validate` rejects atomically;
  `hook.rs::load_shortcuts` falls back per field). A reserved chord parses, so both need a new branch.

The SRS, SDD, `rules-settings.md`, `UC-4`, and `SCN-01` were deliberately **not** edited. `touches` is
filled when a decision is applied, from what actually changed, and an agent must not accept its own
`DEC-`; carrying a draft into the documents it governs would forge the evidence `applied` records.
`OQ-5` and `OQ-9` already anticipated this and stay open until `DEC-003` is applied.

**Corrected the same day**, after the owner asked for a live key-check card in the Shortcuts pane:

- **`DEC-004` widened, and one merge undone.** It had carried reporting and swallowing as a single
  capability on a single lease. That is fine until a second reader needs the report while the pane is
  merely open — then one lease means the keyboard is swallowed for as long as a pane the user may
  leave open stays open, which is `DEC-004`'s own third rejected alternative arriving through a side
  door. Now two leases: **observe** reports and passes through, **record** reports and swallows.
  Title updated; filename deliberately unchanged, because the guide's reason for constraining
  filenames is that renames break links.
- **`DEC-005` added** — the key check reports what was observed and never predicts what will happen.
  It is a decision, not a UI task, because the card's obvious premise is false: an app holding a
  chord through `RegisterHotKey` takes it from the window's queue but does **not** beat a low-level
  hook, so Wira Desk still receives it and the chord works. A card reading window events alone would
  tell the user to abandon a shortcut that functions perfectly — the same wrong-in-both-directions
  failure `DEC-002` refused a probe for. Hence two correlated signals, or no verdict at all.

Three `DEC-` now stand as `draft`. Also worth knowing for whoever implements: `main_window.slint`
wires `key-pressed` only, so there is no key-release signal at all today — modifier state cannot be
released without adding one.

**Corrected a second time the same day**, after the owner asked which arming condition the capture
lease should use. The question rested on a premise nobody had checked — that the lease worked — and it
does not:

- **`DEF-3` opened.** `WM_APP_CAPTURE_LEASE`'s `lParam` is documented in `constants.rs` as a window
  handle, sent by `persistence.rs` as a process id, and converted back in `tray.rs` with
  `GetWindowThreadProcessId`, which fails on a value that is not a handle and leaves its out-parameter
  at `0` — which the hook's own `!= 0` guard then rejects. The lease has never armed.
  `root_cause: architecture`, left `open`: it closes on `DEC-004` being accepted, not on a patch.
  None of this code is in `HEAD` — it is uncommitted work in the working tree.
- **Three reasons it hid, and each is a habit rather than a fact about this bug.** The SSOT was on the
  wrong side, so a review reading either file against the contract would have confirmed that file, and
  a fix touching only the sender leaves the contract sanctioning the bug. The branch is unreachable
  from a test *by construction* — it asks the desktop for the foreground process id, a harness gets
  `0`, and the guard demands non-zero — which is `DEF-1` one branch earlier, above the very seam
  `DEF-1` introduced. And the debug trace prints `arm=true pid=0`, a derived value with no sign of what
  it was derived from, so the log blames the sender.
- **`DEC-004`'s lease table is now three columns, not one.** The hook makes three independent
  decisions — report, suppress Wira Desk's own action, swallow from Windows — and the consultation's
  three options were all one axis. The existing lease is `no / yes / no`; observe is that lease with a
  voice. The only genuine decision left was whether observe suppresses: it must, or pressing a
  configured chord to test the key check switches windows out from under the pane being read.
  Process-id addressing and the `wParam` lease level are written into the decision rather than left to
  the implementation, because the alternative — window handles — is the shape that produced `DEF-3`.
- **`OQ-17` opened** for process-id reuse: disarm-on-every-exit plus heartbeat reaping narrows the hole
  without closing it, and how wide it is has not been measured.

### 2026-08-21 — G3/G4 lens review: structure, prose, edge-case-hunter

Ran the lens set the owner's `risk_accepted: medium` selects, over both SRS and both SDD with their
slots, and the spine at structure/prose. Thirteen findings, all resolved in place except one that
is not this repository's to fix:

- **A contract prescribed behaviour the implementation had deliberately rejected.** The reload
  contract's error table said "Retry once" on a failed post. `signal_reload` does not retry, and the
  SAFETY comment at the call site says why: the post is a nudge to re-read a file that is already
  written, so a failure is reported rather than retried. A builder following the contract would have
  added the retry the author had reasoned their way out of.
- **The Tier-3 flow denied the recovery its own scenario documents.** `flow-hook-death-tier3.md`
  ended with "no longer work until daemon restart", while the attached scenario and the hook state
  machine both describe the heartbeat re-registering the hook and clearing the toast latch with no
  restart. The same diagram also had the heartbeat thread re-registering the hook and setting the
  tray tier; a hook belongs to the thread that installed it, so re-registering it from the heartbeat
  thread would install a hook nobody drains — the one failure this design cannot detect.
- **Two production IPC messages were missing from the API inventory** (refresh-OK and shutdown).
  Refresh-OK is precisely the message that makes recovery restart-free, so its absence hid the
  recovery path from anyone reading the inventory rather than the code.
- **The window-management contract inventory pointed at a contract file that did not exist.** Written
  now, since `mode: deep` requires a spec per endpoint, and the heartbeat is a real boundary.
- **The two settings scenarios were on a different template from the two window-management ones**,
  with no frontmatter at all — no type, id, component, or parent use case. Rewritten onto the shared
  shape. Both also carried the auto-start ownership error: one had the settings process reading a
  `schtasks` exit code it cannot see, and named a config key (`auto_start.enabled`) that does not
  exist. One claimed Save is disabled for an invalid field; Save is unconditional, and rejection
  surfaces as feedback.
- **A VM-bypass step cited the diagnostic-log business rule as its authority.** No cross-component
  rule governs the bypass; the decision invariant alone does.
- **A state-machine section was filed under the wrong entity.** The hook instance's lifecycle carried
  the name of the command entity, whose own lifecycle is three states in the domain model. Two
  machines under one name is how a reader ends up hunting `Degraded` in the wrong table.
- Softened two unfalsifiable performance absolutes in a design summary ("within microseconds",
  "sub-millisecond execution time") to the budget that is actually measured.
