### 2026-08-21 — G3/G4 review: corpus reconciled against shipped code

Reviewed the five binding artifacts (spine, both SRS, both SDD) by verifying their claims against
source rather than reading them for coherence. SDD-window-management's eleven "Verified" rows all
held: `RING_BUFFER_CAPACITY = 16`, `ANTI_MACRO_THROTTLE_MS = 50`, `HOOK_HEARTBEAT_SECS = 10`,
`HOOK_CHECK_FAIL_THRESHOLD = 3`, `HOOK_RETRY_MAX = 5`, the toast latch, `suppress_start_menu`,
`TokenElevation`, `SetDllDirectoryW`, `TaskbarCreated`, and the `1..=5` command enum. Every cited
file exists. The defects were all in documents that had never been checked against the code they
describe — the corpus was harvested from the 2026-07-06 BMAD plan, and the implementation had moved
on or had never matched it:

- **BR-5 and FR-12 described a mechanism that never existed here.** Both said "View Logs" opens the
  log *folder*, and BR-5's enforcement quoted `ShellExecuteW(..., L"explore", log_dir, ...)`.
  `git log -S '"explore"'` returns exactly one commit — the corpus commit. `menu.rs::view_logs`
  has spawned `notepad.exe <log_path>` since the initial public release. Corrected to the file, and
  FR-12's proof-of-done with it: a wrong proof either fails G5 against working code or provokes a
  code change to satisfy a promise nobody made.
- **The auto-start task name was wrong in three places.** `WiraDeskAutoStart` in `business-rules.md`,
  `domain-model.md`, and the PRD; `shared::constants::TASK_NAME` is `"WiraDesk"`. Had a wave
  implemented BR-4 as written, `/Create` and `is_registered`'s `/Query` would have disagreed and the
  menu checkmark would never have lit.
- **Auto-start ownership was attributed to `settings`.** BR-4's enforcement, SRS-settings' constraint,
  the SDD's structure table, its dependency diagram, and UC-6's flow all had the settings process
  calling `schtasks`. `grep schtasks` hits `crates/daemon/` only: settings writes
  `general.auto_start` and signals reload; the daemon reconciles the task, and `schtasks /Query` is
  authoritative for the checkmark.
- **The spine's Stack table was stale on all three pinned crates.** `windows-sys` 0.59.x → 0.52,
  `egui`/`eframe` 0.31.x → 0.35, `toml` 0.8.x → 1.1 (moved by #5, never reflected here).
- **SRS-window-management listed `SetWindowPos` as a non-blocking enumeration API.** It is a mutation
  API belonging to the arrangement engine; replaced with the spine's actual sterilization list.
- Smaller: SRS-WM's success signal claimed "under 1 ms perceived latency" against NFR-2/NFR-3's
  10 ms hook budget; SRS-settings undercounted its local rules as `LBR-ST-1..5` when seven exist,
  and its gate checklist omitted AD-1 and AD-5 that its own Constraints bind; both SRS asserted
  requirements were "ratified at G3" while `gates_passed` read `[G1, G2]`.

No `DEC-` was written for any of these. `decision-guide.md`'s test is whether the answer is readable
from the code in three months, and in every case it is (`menu.rs::view_logs`, `TASK_NAME`,
`daemon/src/autostart.rs`, the manifests). Recording them would have been backfilling from memory,
which the guide forbids.
