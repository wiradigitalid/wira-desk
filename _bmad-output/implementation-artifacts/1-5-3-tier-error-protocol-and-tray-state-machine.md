# Story 1.5: 3-Tier Error Protocol & Tray State Machine

Status: done

## Story

As a pengguna yang membutuhkan keandalan,
I want indikator visual otomatis pada ikon Tray saat terjadi masalah, dan notifikasi darurat jika hook mati,
so that saya segera tahu jika WinTick berhenti berfungsi.

## Acceptance Criteria

1. **Given** WinTick beroperasi normal **When** kegagalan startup terjadi (mis. Hook diblokir AV) **Then** Tier 1 (Fatal): tepat 1x `MessageBox`, lalu exit.
2. **Given** WinTick beroperasi normal **When** error non-fatal runtime dicatat di `wintick.log` **Then** Tier 2 (Warning): ikon Tray menampilkan overlay titik merah kecil, tanpa pop-up.
3. **Given** WinTick beroperasi normal **When** heartbeat monitor (10 detik) mendeteksi hook mati & re-registrasi gagal berulang **Then** Tier 3 (Critical): ikon Tray silang merah besar **dan** tepat 1x Toast Notification **per episode** (guard `hook_dead_toast_sent` mencegah toast berulang dalam satu episode; di-reset saat hook pulih sehingga episode Tier-3 independen berikutnya memunculkan toast baru — semantik "per-episode" di-sign-off pengguna 2026-07-15, lihat Completion Notes).

## Dev Notes

### Arsitektur & Aturan Terkait
- **AD-1 (Actor/Message-Passing):** thread health & log **hanya** `PostMessageW` ke hidden window; **tidak boleh** memanggil `set_state`/`modify_icon`/`TrayData` langsung dari thread lain — hanya thread pemilik window (`wndproc_impl`) yang mengubah state tray **maupun** `HHOOK` (termasuk `SetWindowsHookExW`/`UnhookWindowsHookEx` re-registrasi — `health.rs` tidak boleh menyentuh hook, hanya `PostMessage` tick `WM_APP_HOOK_CHECK`). Ini pola yang sama dipakai hook thread (u8 command via ring buffer) di Epic 2 nanti.
- **AD-7 (3-Tier Protocol):** Tier1 = 1x MessageBox+exit (`error::fatal`); Tier2 = silent log + titik merah (`log::warn` → `WM_APP_LOG_WARNING`); Tier3 = silang merah + 1x Toast (`health` → `WM_APP_HOOK_CHECK` tick → verifikasi/re-install di `wndproc_impl` → `WM_APP_HOOK_DEAD` bila gagal berulang → toast guard di `TrayData`).
- **AD-8 (Hook Health Monitoring):** `health.rs` cek tiap `HOOK_HEARTBEAT_SECS` (10 detik, sudah jadi konstanta) via tick `WM_APP_HOOK_CHECK`; **verifikasi & re-register dieksekusi di main/tray thread** (`wndproc_impl`, bukan `health.rs` — lihat Task 4 untuk rationale threading); gagal berulang → Tier 3. Catatan: Win32 tidak punya sinyal native untuk "hook di-drop diam-diam" — satu-satunya proxy verifikasi realistis untuk story ini adalah skenario unhook paksa di debug build (Task 6).
- **NFR3:** Hindari WinRT toast API yang berat; pakai balloon `NIF_INFO` klasik dari Shell (sudah tersedia via `windows_sys::Win32::UI::Shell`, tidak perlu dependency baru).
- **UX-DR2 (Tray Icon Status):** sudah diimplementasikan sepenuhnya di `icon.rs`/`tray.rs` sejak Story 1.4 — story ini hanya menyambungkan *trigger* (log warning, hook heartbeat), bukan membuat ulang visual state.

  - Wide-string helper: `util::wide()` / `util::fill_wide_buf()` — dipakai untuk semua `*W` API Win32 termasuk `szInfo`/`szInfoTitle` toast di Task 5.
  - `util::message_box()` — sudah jadi satu-satunya jalur `MessageBoxW`; `error::fatal` di Task 3 harus reuse ini, **bukan** membuat wrapper baru.
  - `util::debug_log()` — jalur diagnostik sementara (`OutputDebugStringW`) yang dipakai `tray`/`menu`/`autostart`. Catatan di `util.rs:33` eksplisit menyebut "Story 1.5 akan menyalurkan ini ke AD-7 Tier-2 logger" — pertimbangkan apakah `log::warn()` juga harus menggantikan sebagian pemakaian `debug_log()` untuk kegagalan non-fatal yang sudah ada (mis. `Shell_NotifyIconW(NIM_ADD) failed`), atau tetap dipisah (debug_log = developer-only, log.rs = user-visible Tier 2). Putuskan salah satu — jangan biarkan dua jalur log yang tidak konsisten tanpa keputusan eksplisit di Completion Notes.
  - Pola `catch_unwind` di `wndproc` (`tray.rs:174-184`) membungkus **seluruh** `wndproc_impl` — arm baru untuk toast/state tidak perlu guard tambahan, sudah otomatis terlindungi.

## Review Follow-ups

Temuan code-review adversarial 2026-07-15 (3 lensa fresh-context) yang **non-blocking** — didefer, bukan diperbaiki di story ini:

Benign hari ini (arm `WM_TRAYICON` tak menyentuh `data` setelah `menu::show`), tapi rapuh terhadap edit mendatang. Fix: jangan pegang `&mut` melintasi pompa pesan (re-fetch dari `GWLP_USERDATA`, atau copy nilai sebelum pompa).

Dampak terbatas (proses sedang exit; OS mereklamasi hook saat proses berakhir). Fix opsional: guard `shutting_down`.
